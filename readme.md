
# FinOK — сервіс фінансового консультування

FinOK допомагає власникам бізнесу та підприємцям розв'язувати щоденні фінансові й податкові питання. Цей репозиторій об'єднує веб‑інтерфейс, серверну частину та систему оповіщень, щоб зробити комунікацію між клієнтом і командою швидкою, прозорою та надійною.

**Коротко про ідею**

Клієнт залишає запит на сайті → запит зберігається в базі даних → фоновий воркер доставляє повідомлення команді в Telegram або надсилає електронну пошту. Такий підхід дозволяє оперативно реагувати на звернення і зберігати історію для подальшого аналізу.

**Головні цілі і мотиви**

- Забезпечити простий і швидкий канал комунікації між клієнтом та командою.
- Гарантувати доставку повідомлень через надійну чергу з повторними спробами і логуванням.
- Зберігати всі звернення в базі для аудиту, звітності та аналізу.
- Надати розробникам прості інструменти для локальної роботи, діагностики та розгортання.

---

**Основні можливості**

- Інтерфейс на Vite + React зі сторінками та формами для консультацій.
- Сервер на Express з валідацією, Prisma для роботи з PostgreSQL.
- Telegram‑бот (Telegraf) і фонова система обробки повідомлень (`notificationLog`).
- Надсилання електронних листів через SMTP (опціонально).
- Утиліти: `health-check`, `test-telegram`, `fix-recipients`, `clear-webhook`.

---

**Швидкий старт (локально)**

1) Вимоги

- Node.js (рекомендують v18+)
- PostgreSQL або доступний DATABASE_URL

2) Інсталяція та підготовка

```bash
npm install
npx prisma generate --schema=backend/prisma/schema.prisma
cp .env.example .env
cp backend/.env.example backend/.env
# Відредагуйте .env та backend/.env: DATABASE_URL, BOT_TOKEN, TELEGRAM_TEAM_CHAT_ID, SMTP_*
```

3) Запуск

```bash
# Запустити бекенд
node backend/index.js

# Запустити фронтенд (для розробки)
npm run dev

# Запустити Telegram‑бота та воркер (окремий термінал)
npm run start:bot
```

---

**Як працює Telegram‑воркер**

Воркер читає таблицю `notificationLog` і обробляє повідомлення з `channel = 'telegram'`. Для кожного запису він:

1. Блокує запис для обробки, щоб уникнути дублювання.
2. Надсилає повідомлення у вказаний `recipient` або у `TELEGRAM_TEAM_CHAT_ID` (фолбек).
3. Оновлює статус (`sent` або `failed`) і записує помилку при необхідності; застосовує механізм повторних спроб.

---

**Діагностика — типові ситуації**

- `409 Conflict` при запуску бота: перевірте, чи не запущено іншого екземпляра або webhook; запустіть `telegram-bot/clear-webhook.js`.
- Повідомлення з `recipient: null`: упевніться, що `TELEGRAM_TEAM_CHAT_ID` встановлено у середовищі бекенду або запустіть `telegram-bot/fix-recipients.js`.
- 400 помилки від API: відкрийте DevTools у браузері, перегляньте тіло відповіді; бекенд може містити тимчасові debug‑логи для `/api/public/questions`.
- CORS‑помилки: додайте адресу фронтенду до дозволених у бекенді (наприклад, `https://finok-sh4q.onrender.com`).

---

**Розгортання**

При розгортанні (наприклад, Render) переконайтеся, що в середовищі задані:

- `DATABASE_URL`, `BOT_TOKEN`, `TELEGRAM_TEAM_CHAT_ID`, SMTP‑дані

Бота рекомендується запускати як окремий сервіс (background worker, pm2 або окремий інстанс), щоб уникнути конфліктів webhook/getUpdates.
